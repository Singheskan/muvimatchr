<objective>
Wire the complete vote path end to end for the first time: a session's deck is pinned on first read, a participant submits one swipe against it, the vote is persisted through the existing race-safe upsert inside a session-scoped locked transaction, and a live status read reports progress computed from the database rather than from memory.

Purpose: Phase 4 exists because the prior prototype lost votes and mis-computed completion. Proving one full path — pinned deck to persisted vote to live status — on the first commit is what catches an architectural dead end after one task instead of after ten. Every later plan in this phase expands out from this slice.

Output: V8 Flyway migration, three new `Session` columns, `SessionRepository.lockForUpdate`, `SessionService.pinDeck`/`pinnedMovies`/`pinnedMovieIds`, a pinning branch in `DeckController.getDeck`, two new `VoteRepository` aggregate reads, `VoteService`, `MatchAggregationService`, `VoteController` with two endpoints, and an end-to-end `VoteControllerTest`.
</objective>

<assumption_delta_decision>
The deterministic assumption-delta probe fired `pluralization` on the phase-scope phrase "a **second** vote for the same participant+movie".

- **Primary noun:** the *vote decision* identified by `(session_id, participant_id, movie_id)` — not the submission event.
- **Decision:** `no-change`. The generalized identity is already primary: `uq_vote_session_participant_movie` (V3, Phase 1) names the decision, and the surrogate `id UUID` is a detail of one write. A "second vote" is the same decision restated, which `ON CONFLICT ... DO UPDATE` merges in place. There is no singular assumption left to promote and nothing to add alongside.
- **Invariant test (accepted, implemented in Task 2):** for every participant and every movie in the pinned deck, at most one `vote` row exists and it is retrievable by that triple — asserted after a repeat submission, so a future phase that introduces a second write path cannot land silently.

  <action>
Wire ONE participant's swipe from HTTP through service, repository and Postgres and back out as a live status, touching every layer this phase modifies. No batching, no second call site, real error handling on the single path.

**Migration** — create `V8__add_session_deck_pin_and_genre.sql` adding three nullable columns with no default to `session`: `genre INT`, `pinned_deck JSONB`, `deck_pinned_at TIMESTAMPTZ`. A null `deck_pinned_at` is the "not yet pinned" sentinel (D-04's lazy trigger); a null `genre` means no genre filter, the same optional shape `CatalogReferenceService.requireKnownGenre(genreId: Int?)` already accepts. `ddl-auto=validate` means this migration is the schema push — any Spring-context test failing to boot after it signals a migration/entity mismatch.

**Session entity** — add three constructor parameters with defaults, after `providerIds` and before `createdAt`: `var genre: Int? = null` mapped to column `genre`; `var pinnedDeckJson: String? = null` mapped to column `pinned_deck` with `columnDefinition = "jsonb"` plus the Hibernate JSON type-code annotation copied from `DeckCacheEntry`; `var deckPinnedAt: Instant? = null` mapped to column `deck_pinned_at`. All three `var` — they are written once at pin time.

**SessionRepository** — add `fun lockForUpdate(@Param("sessionId") sessionId: UUID): UUID?` backed by `@Query(value = "SELECT id FROM session WHERE id = CAST(:sessionId AS uuid) FOR UPDATE", nativeQuery = true)`. No `@Modifying` (it is a read). The row-lock clause must be written into the SQL text itself: the Spring Data lock annotation is silently ignored on native queries (04-RESEARCH.md Pitfall A), so it must not be relied on here.

**SessionService** — inject `ObjectMapper` (the `tools.jackson.databind.ObjectMapper` bean, as `MovieCatalogService` does) alongside the existing `SessionRepository`, and add three methods:
- `@Transactional fun pinDeck(sessionId: UUID, genreId: Int?, movies: List<MovieCatalogService.CachedMovie>): Session` — `findById(...).orElseThrow { ResponseStatusException(HttpStatus.NOT_FOUND, "No session with id $sessionId") }`, return the session unchanged if `deckPinnedAt != null` (already pinned, first writer wins), otherwise set `genre = genreId`, `pinnedDeckJson = objectMapper.writeValueAsString(movies)`, `deckPinnedAt = Instant.now()` and `save`.
- `fun pinnedMovies(session: Session): List<MovieCatalogService.CachedMovie>` — deserialize `pinnedDeckJson` with a `TypeReference<List<MovieCatalogService.CachedMovie>>`, returning an empty list when the field is null. This is the single deserialization point; no other class parses that column.
- `fun pinnedMovieIds(session: Session): Set<Long>` — `pinnedMovies(session).map { it.tmdbId }.toSet()`.

**DeckController** — inject `SessionService`. Immediately after the existing session lookup and before `requireKnownGenre`, branch on `session.deckPinnedAt != null`: build and return a `DeckResponse` from the stored snapshot with `sessionId = sessionId`, `status = "ok"`, `stale = false`, `fetchedAt = session.deckPinnedAt!!`, `totalResults = pinnedMovies.size`, and `movies` mapped through the same `DeckMovieResponse`/`DeckProviderResponse` construction the existing `ok` branch uses. On the not-yet-pinned path, leave the existing validation, `movieCatalogService.getDeck(...)` call and both response branches exactly as they are, and call `sessionService.pinDeck(sessionId, genre, result.movies)` only on the branch that returns `status = "ok"` — a result below `MINIMUM_DECK_SIZE` must leave `deck_pinned_at` null so the group can still widen its filters (04-RESEARCH.md Pitfall D: deck size is only ever derived from the pinned snapshot).

**VoteRepository** — add two native reads following the existing named-`@Param` convention, no string interpolation:
- `fun findActiveParticipantIds(@Param("sessionId") sessionId: UUID, @Param("timeoutSeconds") timeoutSeconds: Int): List<UUID>` — select `p.id` from `participant p` with a `LEFT JOIN LATERAL (SELECT MAX(v.voted_at) AS last_voted_at FROM vote v WHERE v.participant_id = p.id AND v.session_id = CAST(:sessionId AS uuid)) lv ON true`, filtered by `p.session_id = CAST(:sessionId AS uuid)` and `COALESCE(lv.last_voted_at, p.created_at) > now() - (CAST(:timeoutSeconds AS int) * INTERVAL '1 second')`, ordered by `p.id`. That `COALESCE` is D-06 stated in one expression: last vote, or join time when the participant has cast none.
- `fun countFinishedParticipants(@Param("sessionId") sessionId: UUID, @Param("participantIds") participantIds: Collection<UUID>, @Param("deckSize") deckSize: Int): Int` — count the rows of an inner `SELECT v.participant_id FROM vote v WHERE v.session_id = CAST(:sessionId AS uuid) AND v.participant_id IN (:participantIds) GROUP BY v.participant_id HAVING COUNT(*) >= :deckSize`.

**MatchAggregationService** — new `@Service` in the `voting` package, constructor-injecting `SessionRepository`, `SessionService` and `VoteRepository`. D-05 rules out both alternatives for an abandoned participant — waiting forever, or a manual exclude/kick action — in favor of a computed timeout, implemented as an `@Value("\${voting.inactivity-timeout-seconds:60}") private var inactivityTimeoutSeconds: Int = 60` field so tests can shrink D-06's one-minute window. It holds no mutable state and caches nothing — every value is recomputed from the database on every call (D-07 forbids a stored or sticky flag; an in-JVM counter or per-session progress map is the exact prior-prototype failure this rebuild exists to remove).
- `fun computeStatus(sessionId: UUID): SessionVoteStatus` — load the session (404 when absent), `deckSize = sessionService.pinnedMovies(session).size`, `activeIds = voteRepository.findActiveParticipantIds(sessionId, inactivityTimeoutSeconds)`. When `activeIds` is empty, return `activeCount = 0`, `finishedCount = 0`, `isComplete = false` without issuing the second query — an empty collection would render an empty `IN ()` list, which Postgres rejects. Otherwise `finishedCount = voteRepository.countFinishedParticipants(sessionId, activeIds, deckSize)` and `isComplete = deckSize > 0 && activeIds.isNotEmpty() && finishedCount == activeIds.size`. The `deckSize > 0` conjunct is load-bearing: without it a freshly created, never-pinned session reports itself complete.
- Declare `data class SessionVoteStatus(val sessionId: UUID, val deckSize: Int, val activeCount: Int, val finishedCount: Int, val isComplete: Boolean)` in this file. Plan 04-03 adds `matchedMovieIds` and `likeCounts` to it.

**VoteService** — new `@Service` in `voting`, constructor-injecting `SessionRepository`, `VoteRepository` and `MatchAggregationService`, with a single `@Transactional fun recordVote(sessionId: UUID, participantId: UUID, movieId: Long, choice: VoteChoice): SessionVoteStatus` that runs exactly three statements in order: `sessionRepository.lockForUpdate(sessionId)`, then `voteRepository.upsertVote(UUID.randomUUID(), sessionId, participantId, movieId, choice.name)`, then `return matchAggregationService.computeStatus(sessionId)`. The transaction annotation belongs on this method and nowhere else in the path — repository methods called from inside it inherit this transaction, and without a single enclosing boundary the row lock is released before the upsert runs (04-RESEARCH.md Pitfall B). Make no outbound HTTP call inside this method: the only catalog-calling path is the deck endpoint, deliberately kept out of the locked window.

**VoteController** — new `@RestController` in `voting` with `@RequestMapping("/api/sessions")`, injecting `SessionRepository`, `SessionService`, `VoteService` and `MatchAggregationService`, and exposing exactly two request mappings and no others:
- `POST /{sessionId}/votes` taking `@PathVariable sessionId: UUID`, `@Valid @RequestBody request: VoteRequest` and `@CurrentParticipant participant: Participant`, returning `VoteStatusResponse`. Guard order: membership first (`participant.session.id != sessionId` → 404 "No such participant in this session", copied verbatim from `DeckController`), then load the session, then reject with 409 "No deck has been pinned for this session yet" when `deckPinnedAt == null`, then reject with 400 "Movie is not part of this session's deck" when `request.movieId !in sessionService.pinnedMovieIds(session)`, and only then call `voteService.recordVote(sessionId, participant.id!!, request.movieId, request.choice)`. The participant identity comes only from the resolved token — never accept a participant id from the body or the query string.
- `GET /{sessionId}/votes/status` taking `@PathVariable sessionId: UUID` and `@CurrentParticipant participant: Participant`, applying the same membership guard, returning `matchAggregationService.computeStatus(sessionId)` mapped to `VoteStatusResponse`.
- Declare `data class VoteRequest(val movieId: Long, val choice: VoteChoice)` and `data class VoteStatusResponse(val sessionId: UUID, val deckSize: Int, val activeCount: Int, val finishedCount: Int, val isComplete: Boolean)` below the controller class, matching `SessionController`'s DTO placement.

**VoteControllerTest** — new test class extending `TmdbMockServerSupport` with `@AutoConfigureMockMvc`, reusing `DeckControllerTest`'s `createSession`/`joinSession` helpers and its `DISCOVER_FIXTURE` + `MULTI_REGION_MOVIE_AVAILABILITY_FIXTURE` fixtures (five movies, five availability responses). Add a private helper that creates a session, joins one participant, enqueues the fixtures, performs the deck GET (which pins), and returns the token plus the pinned movie ids.
