<objective>
Deliver the results view and close RSLT-01 and RSLT-02.

Two requirements land here. RSLT-02: the results screen shows the single best mutual match's poster,
title and where to watch it, with a deterministic rule for "single best" when several films are
unanimous, and D-11's plain no-match message when none are. RSLT-01: a participant who opens their
link after everyone finished - without having been connected when voting completed - is taken
directly to the results view, no dead end, no blank screen, no manual refresh.

This plan also carries the phase's end-to-end verification: the full join-swipe-wait-results journey
through the SPA, including the zero-match case that PITFALLS.md's "Results are correct" checklist
row calls out as the one people never test.

Purpose: this is the screen the entire application exists to produce, and the one place where an
approximation would be a lie rather than a bug.
</objective>

Implements RSLT-02 and D-11.

**frontend/src/results/pickBestMatch.ts.** Export the pure function
`pickBestMatch({ matchedMovieIds, likeCounts, movies }: { matchedMovieIds: number[]; likeCounts: MovieLikeCountResponse[]; movies: DeckMovieResponse[] }): DeckMovieResponse | null`:
1. Return `null` immediately when `matchedMovieIds.length === 0`. This is the single most important line in the file - see the prohibition below.
2. Build `const matchedSet = new Set(matchedMovieIds)` and `const candidates = movies.filter(m => matchedSet.has(m.tmdbId))`. Return `null` when `candidates` is empty.
3. Build a `Map<number, number>` from `likeCounts`, defaulting a missing entry to 0.
4. Sort a copy of `candidates` by like count descending, then `voteAverage` descending, then `tmdbId` ascending. Return the first element.

Step 4's three keys resolve RSLT-02's undefined "single best" as flagged assumption A-02: every
term is server-supplied, and the trailing id key makes the ordering total, so two participants
loading results at the same moment cannot see different films.

`likeCounts` may only reorder a set the server already declared unanimous. It must never be used to
select a film that is absent from `matchedMovieIds`. `MatchAggregationService.perMovieLikeCounts` is
deliberately unfiltered by active roster and by unanimity, so a film with the session's highest like
count can easily be one that somebody passed on. Presenting that as the group's match would tell a
group they agreed on something they did not - prohibition P-01, and the one failure mode on this
screen that is a lie rather than a bug.
