<objective>
Build the swipe deck: a 2-3 card stack whose top card is dragged left or right with real tilt and
colour feedback, whose committed choice is persisted before the next card becomes interactive, and
which flows straight into the waiting route when the deck runs out.

This is the first horizontal expansion off the tracer 06-01 proved. It delivers ROADMAP Phase 6
Success Criterion 4 ("the swipe deck UI responds to left/right drag gestures and visually reflects
each pass/like before advancing") and decisions D-06 through D-09, and it is the only thing that
makes "everyone has finished" reachable through the SPA at all - which is why it carries RSLT-01.

Purpose: the deck is the app's signature interaction and the one screen where a wrong abstraction
is expensive to undo. Output: a working, resumable, server-backed swipe deck.
</objective>

**frontend/src/swipe/swipeDecision.ts.** Export the constants `SWIPE_COMMIT_DISTANCE = 120`,
`SWIPE_COMMIT_VELOCITY = 500`, `SWIPE_MIN_INTENT_DISTANCE = 40`, `SWIPE_TILT_DEGREES = 18`,
`SWIPE_TILT_RANGE = 200`, and the pure function
`resolveSwipe({ offsetX, velocityX }: { offsetX: number; velocityX: number }): VoteChoice | null`
with these rules in order:
1. `offsetX >= SWIPE_COMMIT_DISTANCE` returns `'LIKE'`; `offsetX <= -SWIPE_COMMIT_DISTANCE` returns `'PASS'`.
2. `velocityX >= SWIPE_COMMIT_VELOCITY && offsetX >= SWIPE_MIN_INTENT_DISTANCE` returns `'LIKE'`; `velocityX <= -SWIPE_COMMIT_VELOCITY && offsetX <= -SWIPE_MIN_INTENT_DISTANCE` returns `'PASS'`.
3. Otherwise `null`.

The `SWIPE_MIN_INTENT_DISTANCE` conjunct on the velocity branch is what stops a fast correction
flick in the opposite direction registering as a deliberate vote. That is prohibition P-03
expressed in the decision rule itself, not a nicety - do not simplify the velocity branch to a
bare velocity comparison.

**frontend/src/swipe/SwipeCard.tsx.** Export `SwipeCard({ movie, isTop, onVote, disabled })`.
Use the drag/gesture API imported from `motion/react` - the current package name of the library
STACK.md locks in. Do not add a second gesture or spring library alongside it. On the front card
set `drag="x"`, `dragElastic={0.6}`, `dragSnapToOrigin`, and an `onDragEnd` handler that reads
`info.offset.x` and `info.velocity.x`, passes them to `resolveSwipe`, and calls `onVote(choice)`
only when the result is non-null. Create `const x = useMotionValue(0)` and derive three values from

- rotation: `useTransform(x, [-SWIPE_TILT_RANGE, 0, SWIPE_TILT_RANGE], [-SWIPE_TILT_DEGREES, 0, SWIPE_TILT_DEGREES])`

**frontend/src/session/useDeck.ts.** Export `useDeck(sessionId, token)`: a TanStack Query
`useQuery` with `queryKey: ['deck', sessionId]`, `enabled: Boolean(sessionId && token)`,
`staleTime: Infinity` and `retry: 1`. Infinite stale time is correct and deliberate: once pinned,
the deck is immutable for the life of the session (Phase 4 D-01), so refetching it can only cost a
round trip and can never produce different content. The first successful call is also what pins the
deck server-side, which is the intended lazy trigger - not a side effect to avoid.

**frontend/src/routes/SwipeScreen.tsx.** Export `SwipeScreen`. Read `code` from `useParams`, the
token from `useSessionToken()`, and call `useBootstrap(code, token)` then `useDeck(bootstrap?.sessionId, token)`.

Branches, in order:
1. No token: `navigate(\`/s/${code}\`, { replace: true })` in an effect and render nothing. Routing is presentation only (D-04) - the backend remains the access boundary, so this redirect is a convenience, not a security control.
2. Bootstrap or deck loading: a loading state.
3. Bootstrap error: render the message from `ApiError` and a link back to `/s/{code}`.
4. `deck.status === 'insufficient_results'`: render a heading and a body naming `deck.totalResults` and explaining that the current genre/region/provider filters matched too few titles. Render no card stack. Do not fall back to an unfiltered deck, do not pad the list, and do not retry with widened filters - the backend deliberately refuses to substitute content the filter excluded, and the SPA must not undo that.
5. Otherwise render the deck.

Derive the remaining queue once with `useMemo`:
`const remaining = deck.movies.filter(m => !votedSet.has(m.tmdbId))` where `votedSet` is a `Set`
built from `bootstrap.votedMovieIds`. Hold a `cursor` number in state starting at 0; the stack is
`remaining.slice(cursor)`. Reading the resume position from the server-issued `votedMovieIds`
rather than from any local record is what makes a reopened link resume rather than restart.

Define one `commitVote(choice: VoteChoice)` used by both the drag path and the button path:
1. Guard: return immediately if a vote is already in flight or the queue is empty.
2. Set `pending` true (which passes `disabled` down to `CardStack`, freezing drag on the next card).
3. `await postVote(bootstrap.sessionId, token, currentMovie.tmdbId, choice)`.
4. On success: clear any error, increment `cursor`, and clear `pending`. If the new cursor has reached `remaining.length`, `navigate(\`/s/${code}/wait\`, { replace: true })` - D-08's straight-through transition, with `replace` so the back button cannot return to an exhausted deck.
5. On `ApiError`: clear `pending`, keep `cursor` where it is, and set an error message. Map 409 to "The deck is not ready yet - reload the page.", 400 to "That film is not part of this session's deck.", 401 to "Your link is no longer valid.", and anything else to the error's own message. Never advance the cursor on a failed vote and never retry automatically - prohibition P-03 makes a silently-dropped vote worse than a visible error.

Do not derive any completion state here. The POST response carries a full `VoteStatusResponse`, but
this screen must not read or branch on its session-level completion flag; the waiting route owns
that decision (prohibition P-02, and it keeps one screen responsible for one transition).
